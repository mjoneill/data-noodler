# Pinned dependency versions for analytics-mcp 1.1.0 (mcp 2.x).
#
# WHY THIS EXISTS
# Installing without constraints made pip backtrack through roughly 30
# versions of google-adk on a colleague's Windows machine before settling,
# taking several minutes and printing "This is taking longer than usual".
# It succeeded, and it was neither fast nor reproducible: two people running
# the identical command can end up with different trees.
#
# This is DATA, not a program. It records a set of versions observed working
# together, so an install is fast and identical everywhere.
#
# HOW TO USE IT
#   pip install -c constraints.txt analytics-mcp==1.1.0 google-auth-oauthlib
#
# A constraints file only bounds packages that are actually installed; it
# never causes one to be installed. So this is safe to use on any platform
# even though it was captured on one: Windows-only dependencies such as
# pywin32 are absent here and simply go unconstrained rather than conflicting.
#
# HOW TO REGENERATE
# Capture it from an interpreter where the servers are known to work, with
# installer/freeze_constraints.py. Do not hand-edit: a version nobody has run
# is a guess with the authority of a pin.
#
# Regenerate into a scratch file and replace only the pin lines below, so
# this header survives: freeze_constraints.py prints pins, not this text.
#
# SECURITY: SCAN BEFORE SHIPPING
# A pin freezes a version's vulnerabilities along with its behaviour. The
# 2026-09-14 set aged into PyJWT 2.13.0 (critical), urllib3 2.7.0,
# cryptography 49.0.0 and a certifi that still trusted compromised roots, and
# every Windows install got them, because this file is that install path
# (found 2026-10-23, #151). Before every zip:
#
#   uvx pip-audit --no-deps --disable-pip -s osv \
#       -r data-noodler/installer/constraints.txt
#
# Ship only on exit 0. tests/test_constraints_security.py holds offline
# floors for the versions found vulnerable, so they cannot come back.
#
# NO EXCEPTIONS since 2026-11-20 (#1986). CVE-2026-114603 (opentelemetry-api
# tracestate parsing) was accepted from 2026-10-25 because google-adk capped
# opentelemetry at <=1.44; google-adk 2.15.0 allows 1.45.2, which fixes it.
# The parsing stays switched off anyway, as defence in depth: nothing here
# exports traces, so parsing them buys nothing. OTEL_PROPAGATORS=none is set
# in the launchers and the Windows entries, and data-noodler drops the SDK's
# tracing middleware. tests/test_mcp2_security.py holds the switch-off.
#
# pip is pinned too, so the venv's own pip is upgraded with -c: pip below
# 26.2.2 vendors the compromised roots.
#
# Captured 2026-11-20 on a clean macOS runner (GitHub Actions, Python
# 3.12.10) by .github/workflows/refresh-pins.yml: the 2026-10-25 set with
# only oauthlib, pyasn1, opentelemetry-api/sdk and google-adk bumped, and
# google-genai, watchdog and opentelemetry-semantic-conventions released to
# follow google-adk 2.15.0. 68 distributions; 8 changed, the rest identical.
# The full suite passed against it (901 tests) and the OSV scan above exits 0
# with no exceptions. Previous capture: 2026-10-25, Python 3.12.13 and 3.14.9.
